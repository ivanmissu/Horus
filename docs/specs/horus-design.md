## 1. 背景与产品定位

团队负责人同时管理多个研发方向，需求散落在人脑、周会和聊天记录里，缺少一个地方能回答：

1. **本周新建的需求，都走到研发流程的哪个节点了？**
2. **有什么东西卡住了？**
3. **哪些高危需求快炸了（逾期）？**

Horus 是一个以"**软件研发流程的重要节点 = 里程碑**"为核心模型的团队负责人掌控工具。

**它不是**：任务看板、工时/日报系统、全员协作平台、外部需求系统的聚合报表（集成是后续演进方向）。

**成功标准**：负责人每天打开首页（手机或电脑），1 分钟内对当前在途需求的节点分布、卡点、逾期情况心里有数。

## 2. 用户与角色

| 角色 | 人数（当前） | 使用方式 |
|------|--------------|----------|
| 团队负责人 | 1 | 主要消费者：看首页聚合、团队详情、钉钉推送；管理成员账号、团队、阶段模板、PM 归属 |
| 产品经理（PM） | ≤ 3，各绑定不同团队 | 主要维护者：桌面端录入需求、更新阶段、标记卡点 |

登录方式：**轻登录**。负责人为成员预建账号，成员首次登录设置密码。无自助注册、无找回密码流程。

访问场景：PM 在电脑端维护数据；负责人常在手机/会议场景打开首页**只读浏览**。

团队规模：约 3~5 个团队，单团队每周新增需求 3~5 条；大需求工期约单月，小需求约单周。

## 3. 核心概念与领域模型

```
团队 Team
 ├─ 阶段模板 StageTemplate
 │    默认八段：需求评审 → 技术方案设计 → 开发完成 → 联调完成 →
 │              提测 → 测试通过 → 预发布验证 → 正式上线
 │    团队级可自定义：增删阶段、改名、调整顺序
 └─ 需求 Requirement
      ├─ 标题（必填）
      ├─ 描述（一句话概要即可）
      ├─ 优先级：高 / 中 / 低
      ├─ 需求负责人：人名（自由文本或从成员选择，见 §8 开放点）
      ├─ 期望上线/完成日期（必填；不涉及上线的需求填完成时间；新建只允许当天及以后）
      ├─ 卡点标记：有 / 无 + 原因说明
      ├─ 当前阶段 + 进入该阶段的时间（唯一的阶段时间记录，无历史流水）
      ├─ 来源字段 + 外部 ID（V1 恒为"手工录入"，为后续集成预留）
      └─ 状态：在途 / 已上线（含待归档与已归档，归档以 archivedAt 标记） / 已取消（手动标记，立即归档）

成员 Member（负责人、PM；账号信息 + 角色 + 团队绑定）
```

层级到"团队 → 需求"为止，V1 不设团队之下的项目/版本/迭代层。团队是稳定组织单元，不关闭、不归档。

### 3.1 阶段推进规则

- **可向前跳过**阶段（如小需求不需联调，从"开发完成"直接到"提测"）。
- **不可回退**。测试打回等情形不建模为状态回退，由卡点标记表达。
- 每次阶段变更自动记录**进入新阶段的时间**；首页/列表展示"阶段停留天数"。
- "正式上线"到达时需求标记为已上线，仍保留在在途视图；由负责人手动归档后才离开在途视图。

### 3.2 状态与归档

| 状态 | 触发 | 后果 |
|------|------|------|
| 在途 | 新建需求 | 参与在途统计，并出现在工作台列表 |
| 已上线 | 推进到最后一个阶段"正式上线" | 信息只读，保留在在途列表中，等待负责人手动归档 |
| 已归档 | 负责人对已上线需求手动归档 | 离开一切在途视图与工作台列表，记录只读、不可恢复 |
| 已取消 | PM 手动标记"不做了" | 立即归档，保留记录可查 |

已归档与已取消均为终态；归档只对已上线需求开放，且不支持撤销。

## 4. 功能需求

### FR-1 首页 · 全部在途视图（核心体验）

首页展示**全部未归档需求**（含已上线待归档），**按团队分组**（预计总量十几~二十几条，一页看完，不做分页）。已上线未归档的需求标记「已上线 / 待归档」，归档后进入归档历史。

在此基础上，以下三类风险以标记高亮，并可通过顶部标签快速筛选：

1. **本周新建**：创建时间在本自然周（周一 00:00 Asia/Shanghai 起）内且仍在推进中的需求，显示其当前节点。
2. **卡点**：所有带卡点标记的需求（不限创建时间），显示卡点原因。
3. **逾期**：已过期望上线/完成日期、仍未上线或收尾（不限优先级）；其中优先级 = 高的部分单独计为**高优逾期**，两者分别有一张统计卡片与筛选标签。

统计卡片「全部在途」与列表行数使用同一口径（未归档），侧边栏团队数字与团队详情「在途需求」保持一致。

每条需求展示字段：标题、所属团队、当前阶段、阶段停留天数、需求负责人、期望上线/完成日期、状态标记（新建/卡点/逾期/已上线待归档，可叠加命中多条规则）。

移动端同一页面、只读、分组可折叠。

### FR-2 团队详情页

- 顶部：**阶段分布漏斗/条形视图**——该团队在途需求在八个（或自定义）阶段上的数量分布，用于发现流程瓶颈。
- 在途需求列表：支持按阶段 / 优先级 / 需求负责人 / 有无卡点筛选，支持排序。
- 归档历史：已手动归档的上线需求与已取消需求按时间倒序查询。
- PM 在本页创建需求、推进阶段、编辑字段、标记/解除卡点。

### FR-3 需求管理操作

- 创建：标题与期望上线/完成日期必填（后者是逾期标记、预期达成率与钉钉摘要的输入）；优先级默认高优先级、可下调。日期选择器只放开当天及以后（按北京时间），避免需求一创建就已「逾期」；编辑既有需求时下限放宽为该需求已填的日期，历史数据仍可原样保存或往后调整。校验只在前端，接口与脚本导入不受限制，便于批量补录。
- 阶段推进：选择目标阶段（允许向前跳过、禁止回退），系统记录进入时间。
- 卡点：标记 + 原因；解除标记。
- 归档：仅已上线且未归档的需求可手动归档，归档后只读、不可恢复。
- 取消：标记"不做了"，立即进入归档。
- 每次变更记录操作人（数据留痕，页面不展示历史流，为后续扩展预留）。

### FR-4 阶段模板自定义

负责人可为每个团队在默认八段基础上增删阶段、改名、调序。修改模板只影响该团队后续的推进选择；已存在需求若停留在被删除的阶段，系统强制迁移到指定阶段（见 §6 异常处理）。

### FR-5 成员与团队管理（负责人专属）

- 创建/停用成员账号，分配角色（负责人 / PM）。
- 创建团队；为 PM 绑定可维护的团队。
- 团队 ↔ PM 关系：一个 PM 可负责多个团队，一个团队可有多个 PM（保持灵活，V1 不做审批/交叉限制）。

### FR-6 钉钉每日异常摘要

- 每日定时（默认 09:30，可配置）推送：**卡点清单 + 逾期清单（不限优先级，逐条标注优先级）**，格式为钉钉 Markdown 消息，附系统链接。
- 通道：钉钉自定义机器人 Webhook（群机器人），地址由负责人配置。
- 推送失败处理见 §6。

## 5. 非功能需求

| 编号 | 要求 |
|------|------|
| NFR-1 | 内网部署：Next.js 全栈单体应用（容器化单实例）+ MySQL |
| NFR-2 | 数据规模极小（百级团队/需求），无性能特殊要求；页面加载 < 2s 即可 |
| NFR-3 | 移动端浏览器只读体验良好（首页、团队详情），无需原生 App |
| NFR-4 | 备份走公司常规 MySQL 运维；数据量小，恢复目标是"能找回库" |
| NFR-5 | 需求记录保留"来源 + 外部 ID"字段，V1 恒为手工录入，后续集成外部需求系统不改动现有表结构 |
| NFR-6 | 账号密码存库需哈希（bcrypt/argon2），不做明文 |

## 6. 异常与边界处理

- **删除自定义阶段时**：若仍有需求停留在该阶段，强制选择迁移目标阶段，不允许静默丢数据。
- **期望上线/完成日期缺失**：规则 3（逾期）不命中该需求，不算错，列表以中性色提示"未填期望上线/完成日期"。新建入口已改为必填，因此这条只出现在版本升级前的存量数据或由接口写入的需求上。
- **钉钉推送失败**：记录失败日志，次日重试合并推送；不在页面制造打扰式报错。
- **PM 离职/停用**：账号停用不影响其创建的历史需求；需求负责人为文本字段时不受账号影响（见 §8）。
- **并发编辑**：小团队互信场景，后写覆盖即可，不做冲突弹窗（操作留痕可查）。

## 7. 明确不做（V1 范围外）

| 项 | 说明 |
|----|------|
| 每周时间去向 / 工时填报 | 负责人已识别的需求（想看开发/测试每周时间花在哪），**产品形态待定，负责人想清楚后作为独立方向重新做需求分析** |
| 外部系统集成（Jira/TAPD/禅道等） | 仅通过来源字段预留接口可能 |
| 阶段历史流水 / 报表 | 只记当前阶段 + 进入时间 |
| 自助注册、找回密码 | 负责人建号 |
| 审批流、评论区、复杂权限矩阵 | 不做 |
| 需求父子拆分 | 不做，需求单层 |

## 8. 开放点（不阻塞 V1，待实施期确认）

1. "需求负责人"是自由文本还是必须关联成员账号（开发/测试人员不在成员体系里，V1 倾向自由文本）。
2. 「本周新建」固定为自然周（周一 00:00 Asia/Shanghai），不再提供窗口天数配置。

## 9. 决策记录（需求方逐节确认的结论）

| 决策点 | 结论 |
|--------|------|
| 核心使用者 | 团队负责人 |
| 数据来源 | V1 手工录入 |
| 里程碑定义 | 流程阶段型：需求评审→技术方案设计→开发完成→联调完成→提测→测试通过→预发布验证→正式上线 |
| 项目 vs 团队 | 不设项目层，顶层容器为**团队** |
| 阶段模板 | 默认八段，团队级可自定义 |
| 推进规则 | 可跳过、不可回退 |
| 阶段时间 | 仅记当前阶段 + 进入时间 |
| 需求字段 | 标题、描述、负责人、优先级、期望上线/完成日期、卡点标记、当前阶段+时间 |
| 登录/权限 | 轻登录；PM 编辑绑定团队，负责人全局 |
| 规模 | PM ≤3，团队 3~5，单团队周新增需求 3~5 |
| 首页 | 全部未归档需求按团队分组；本周新建、卡点、逾期（含高优逾期）高亮与筛选 |
| 需求统计 | 按自然周/自然月汇总新建、上线、取消、卡点、归档、存量与逾期，支持团队对比与趋势 |
| 产品形态 | Web；PM 桌面录入，负责人桌面+移动只读 |
| 推送 | 钉钉自定义机器人，每日异常摘要 |
| 终态 | 上线后手动归档；加"已取消"终态（选 A） |
| 技术栈 | Next.js 全栈单体 + MySQL（原推荐 SQLite，需求方指定 MySQL） |
