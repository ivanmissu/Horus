# Horus · 研发进程，尽在掌握

基于 Horus V1 PRD 的可交互全栈产品原型。Next.js App Router + React + Drizzle ORM。所有业务操作存入 PostgreSQL，不是静态页面或浏览器本地存储演示。

## 直接体验

首页默认进入公开演示工作空间，无需登录。预置 4 个团队、34 条在途需求、8 条归档记录和 4 个成员，所有时间均以初始化日期为基准。

- 工作台：近 7 天新建、卡点、高优逾期三条规则取并集，按团队展示。
- 团队详情：阶段分布图、筛选与排序、在途和归档列表。
- 需求详情：创建、编辑、跳阶段推进、卡点标记和解除、取消、上线自动归档。
- 阶段模板：团队独立配置，支持重命名、拖动/按钮排序、添加与删除；有记录的删除阶段必须指定迁移目标。
- 成员与团队：预建账号、角色分配、多对多 PM 绑定、账号停用。
- 通知设置：钉钉 Webhook、可选加签、北京时间每日定时发送、实时消息预览和发送日志。发送失败内容会保留并在下次定时推送时合并。
- 手机：首页与团队详情只读，可展开团队、筛选和查看需求；写操作在界面与客户端动作入口被禁用。

## 登录

演示账号：负责人 `chen`，产品经理 `lin`、`su`、`zhou`。账号首次登录时由使用者设置 8–72 位密码，无固定默认密码。密码使用 bcrypt 哈希；会话为 7 天 HTTP-only Cookie，服务端只存会话 token 的 SHA-256 摘要。成员停用后现有会话立即失效。

**公开演示模式有意提供负责人权限，不可直接用于存放真实公司数据。** 正式部署必须设置 `HORUS_REQUIRE_LOGIN=true`，关闭无账号演示入口。在接入真实业务前应由负责人在受控内网完成首次账号初始化，移除演示数据并配置公司安全策略。

## 环境变量

- `DATABASE_URL`：PostgreSQL 连接地址，平台已配置。
- `HORUS_REQUIRE_LOGIN=true`：强制账号登录；未设置时为方便预览的公开演示模式。
- `APP_URL`：可选，系统对外访问地址；通知页面设置的链接优先。

Webhook 和加签密钥仅保存在服务端，工作空间 API 仅返回「是否配置」，不返回其明文。管理员修改配置时留空会保留现有值；可单独移除已保存的加签密钥。

## 开发与验证

1. 安装依赖：`npm install`
2. 启动 PostgreSQL 并配置 `.env`。
3. 应用表结构：`npx drizzle-kit push`
4. 开发启动：`npm run dev`
5. 验证：`npx next typegen`、`npm exec tsc -- --noEmit --pretty false`、`npm run build`
6. 浏览器与接口验收：生产预览在线时执行 `node --experimental-strip-types tests/acceptance.mjs`。需要先运行 `npx playwright install --with-deps chromium`。测试创建独立临时团队和成员，完成后通过 Drizzle 清理，不改动演示业务数据。

## 调度与边界

- `src/instrumentation.ts` 在 Node 服务启动时启动分钟级调度，适用于 PRD 的单实例、持续在线部署。时区固定为 `Asia/Shanghai`。
- 到达当天设定时间后执行一次；当天失败不会持续重试打扰，次日合并重试。重启错过时点后会在当天补发。
- 立即发送测试使用已经保存的配置，真实调用钉钉机器人接口。未提供 Webhook 时不会伪造发送成功。
- 所有数据变更记录操作人；详情展示最近操作人，不实现阶段历史流水 UI。
- 需求负责人为自由文本，来源固定「手工录入」，外部 ID 保留。
- 归档记录只读，取消不可撤销；缺失期望日期不参与高优逾期规则。

## 与生产 PRD 的区别

当前预览平台使用 **PostgreSQL**，而 PRD 指定生产环境使用 MySQL。此原型遵循平台数据库约束，尚未做 MySQL 迁移。生产交付时需将 Drizzle schema 迁移至 `mysql-core`，调整 PostgreSQL advisory lock 与数据库驱动，并接入公司数据库备份、容器运行、内网访问控制与密钥管理。当前提供的是可运行、可保存的在线产品原型，不声明已完成上述公司级生产部署。
